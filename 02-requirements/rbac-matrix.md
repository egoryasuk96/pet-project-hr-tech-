# Матрица прав доступа (RBAC)

**Проект:** Employee Service  
**Документ:** RBAC Matrix  
**Версия:** 1.0  
**Статус:** Draft (Этап 2)

**Обозначения:**  
`C` — create · `R` — read · `U` — update · `D` — delete · `A` — action · `—` — нет доступа

Права пользователя с несколькими ролями объединяются (**union**, BR-16).

- Для комментариев согласующего достаточно комментария в составе действия A (approve/reject/return); отдельный свободный чат не требуется.

## 2. Ограничения доступа (обязательные)

### ACL-01 — Чужие заявки сотрудника
`employee` не может читать/изменять/отменять заявку другого инициатора (BR-01).  
Ожидаемый результат: **404** (предложение NFR-SEC-05) или **403**.

### ACL-02 — Чужие задачи согласующего
`approver` не может approve/reject/return по задаче, где он не assignee (BR-15). → **403** / ERR-FORBIDDEN-APPROVAL.

### ACL-03 — Самосогласование
Инициатор не выполняет решения по своей заявке (BR-21). → **403**.

### ACL-04 — Недоступность админки
`employee` и `approver` без роли `admin` не имеют доступа к административной конфигурации. → **403**.

### ACL-05 — Неактивный тип
Создание заявки по неактивному типу запрещено (BR-10). → ERR-INACTIVE-TYPE.

### ACL-06 — Недопустимый статус для действия
Submit/cancel/edit/approve и т.д. вне допустимых статусов → ERR-INVALID-STATE.

### ACL-07 — Завершённая задача
Повторное действие по завершённой задаче запрещено (NFR-REL-02). → ERR-TASK-DONE / ERR-DUP-ACTION.

### ACL-08 — Множественные роли
Пользователь `employee+approver` получает обе группы прав; проверки владения/assignee сохраняются.
