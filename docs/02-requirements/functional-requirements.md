## 3. REQ — Жизненный цикл заявки

### FR-REQ-01 — Создание заявки
| Поле | Содержание |
| :--- | :--- |
| **Название** | Создание заявки в статусе draft |
| **Описание** | Сотрудник создаёт заявку выбранного активного типа; статус = `draft` |
| **Actor** | employee |
| **Preconditions** | Тип активен (BR-10) |
| **Основной сценарий** | 1) Выбор типа 2) Создание заявки 3) Система сохраняет draft, инициатор = текущий пользователь |
| **Альтернативы / исключения** | Неактивный тип → ERR_INACTIVE_TYPE |
| **Postconditions** | Заявка `draft`; запись в истории (BR-24) |
| **Связи** | BR-19; UC-04; AC-APP-01 |

### FR-REQ-02 — Заполнение полей
| Поле | Содержание |
| :--- | :--- |
| **Название** | Заполнение / изменение полей заявки |
| **Описание** | Инициатор сохраняет значения полей по **актуальной** схеме типа (BR-26) |
| **Actor** | employee (инициатор) |
| **Preconditions** | Заявка в `draft` или `returned`; пользователь — инициатор |
| **Основной сценарий** | 1) Система отдаёт актуальную схему 2) Ввод значений 3) Валидация по актуальной схеме 4) Сохранение |
| **Альтернативы / исключения** | Ошибка валидации → ERR_VALIDATION; неверный статус → ERR_INVALID_STATE; не владелец → ERR_NOT_FOUND |
| **Postconditions** | Значения обновлены; при returned — факт изменения отражается в истории (BR-24) |
| **Связи** | BR-06, BR-19, BR-26; UC-04, UC-09; AC-DRAFT-01 |

### FR-REQ-03 — Отправка на согласование (submit)
| Поле | Содержание |
| :--- | :--- |
| **Название** | Submit заявки |
| **Описание** | Инициатор отправляет заявку из `draft` (первый submit) или `returned` (повторный). При первом submit создаётся экземпляр маршрута (BR-08). При любом успешном submit создаётся **версия** схемы и значений полей с номером отправки (BR-26); решение согласующего привязано к версии. Статус → `in_approval`. Создаются задачи **первого** этапа (при resubmit — тоже этап 1, BR-06). Перед submit — валидация по актуальной схеме и проверка маршрута (BR-18). Механика: [Snapshot Model](../03-diagrams/erd/snapshot-model.md) |
| **Actor** | employee (инициатор) |
| **Preconditions** | Статус `draft` или `returned`; обязательные поля валидны по актуальной схеме; маршрут валиден (BR-18); тип активен |
| **Основной сценарий** | 1) Submit 2) Валидация полей по актуальной схеме 3) Проверка маршрута 4) Экземпляр маршрута (если первый) 5) Новая версия схемы и значений 6) Статус in_approval 7) Задачи этапа 8) История (in-app уведомления — [docs/backlog.md](../backlog.md)) |
| **Альтернативы / исключения** | ERR_VALIDATION; ERR_ROUTE_CONFIG; ERR_INVALID_STATE; ERR_INACTIVE_TYPE |
| **Postconditions** | BR-20; задачи созданы; версия значений зафиксирована; маршрут по BR-08/BR-22 |
| **Связи** | BR-08, BR-18, BR-20, BR-22, BR-26; UC-05; AC-APP-02, AC-APP-02b, AC-APP-03, AC-APP-08, AC-APP-10, AC-DRAFT-01, AC-DRAFT-02; уведомления — [docs/backlog.md](../backlog.md) |

| **Альтернативы / исключения** | Нет доступа → ERR_NOT_FOUND / ERR_FORBIDDEN |

### FR-REQ-06 — Комментарии
| Поле | Содержание |
| :--- | :--- |
| **Название** | Комментарии к заявке |
| **Описание** | Инициатор может добавлять свободные комментарии к своей заявке в статусах, включая `in_approval` (BR-28). Согласующий добавляет комментарий в составе решения (для reject/return — обязательно, BR-25). Комментарии отображаются в карточке |

| **Preconditions** | Доступ к заявке; для свободного комментария инициатора — заявка принадлежит ему |
| **Основной сценарий** | 1) Ввод текста 2) Сохранение 3) Отображение в ленте |
| **Альтернативы / исключения** | ERR_VALIDATION (пустой); ERR_FORBIDDEN / ERR_NOT_FOUND |
| **Postconditions** | Комментарий сохранён |
| **Связи** | BR-25, BR-28; UC-06, UC-07–09; AC-REQ-06 |

## 4. APP — Согласование

### FR-APP-01 — Очередь задач
| Поле | Содержание |
| :--- | :--- |
| **Название** | Получение очереди задач согласующего |
| **Описание** | Approver получает список своих открытых задач |
| **Actor** | approver |
| **Preconditions** | Роль approver |
| **Основной сценарий** | 1) Открытие очереди 2) Список задач: заявка, тип, этап, дата |
| **Альтернативы / исключения** | Пустая очередь допустима |
| **Postconditions** | — |
| **Связи** | BR-14; UC-07 |

### FR-APP-02 — Просмотр задачи
| Поле | Содержание |
| :--- | :--- |
| **Название** | Просмотр задачи и связанной заявки |
| **Описание** | Approver открывает задачу и видит **полную карточку** связанной заявки (поля, статус, этап, комментарии, история в рамках прав) — для активной или завершённой своей задачи (BR-14) |
| **Actor** | approver (assignee) |
| **Preconditions** | Задача принадлежит пользователю (любой статус задачи) |
| **Основной сценарий** | 1) Открытие 2) Полная карточка заявки + этап + доступные действия (если задача открыта) |
| **Альтернативы / исключения** | Нет связанной задачи → ERR_NOT_FOUND / ERR_FORBIDDEN_APPROVAL |
| **Postconditions** | — |
| **Связи** | BR-14, BR-15; UC-07; AC-ACC-06 |

### FR-APP-03 — Approve
| Поле | Содержание |
| :--- | :--- |
| **Название** | Согласование этапа |
| **Описание** | Assignee выполняет approve; срабатывает first-approve wins (BR-03); переход к следующему этапу или завершение (FR-APP-06/07) |
| **Actor** | approver |
| **Preconditions** | Открытая задача; не инициатор (BR-21) |
| **Основной сценарий** | 1) Approve (комментарий необязателен, BR-25) 2) Задача completed 3) Прочие активные задачи этапа → `cancelled` (BR-03) 4) Переход/завершение 5) История |
| **Альтернативы / исключения** | ERR_FORBIDDEN_APPROVAL; ERR_TASK_DONE; ERR_DUP_ACTION |
| **Postconditions** | Этап завершён успешно |
| **Связи** | BR-03, BR-21, BR-25; UC-07; AC-APP-04, AC-APP-09 |

### FR-APP-04 — Reject
| Поле | Содержание |
| :--- | :--- |
| **Название** | Отклонение заявки |
| **Описание** | Reject завершает заявку (`rejected`), закрывает открытые задачи текущего этапа |
| **Actor** | approver |
| **Preconditions** | Открытая задача; BR-21 |
| **Основной сценарий** | 1) Reject + **обязательный** комментарий (BR-25) 2) Статус rejected 3) Закрытие задач 4) История |
| **Альтернативы / исключения** | ERR_FORBIDDEN_APPROVAL; ERR_TASK_DONE; пустой комментарий → ERR_VALIDATION |
| **Postconditions** | BR-04; маршрут завершён |
| **Связи** | BR-04, BR-21, BR-25; UC-08; AC-APP-06 |

### FR-APP-05 — Return
| Поле | Содержание |
| :--- | :--- |
| **Название** | Возврат на доработку |
| **Описание** | Return → `returned`; сохраняется номер этапа; задачи этапа закрываются |
| **Actor** | approver |
| **Preconditions** | Открытая задача; BR-21 |
| **Основной сценарий** | 1) Return + **обязательный** комментарий (BR-25) 2) Статус returned 3) Закрытие задач 4) История |
| **Альтернативы / исключения** | ERR_FORBIDDEN_APPROVAL; ERR_TASK_DONE; пустой комментарий → ERR_VALIDATION |
| **Postconditions** | BR-05; FR-REQ-08 |
| **Связи** | BR-05, BR-21, BR-25; UC-09; AC-APP-07 |

### FR-APP-06 — Переход к следующему этапу
| Поле | Содержание |
| :--- | :--- |
| **Название** | Переход после approve |
| **Описание** | Если после approve есть следующий этап в RouteInstance, система делает его текущим и создаёт задачи назначенным согласующим |
| **Actor** | Система |
| **Preconditions** | Успешный approve; есть следующий этап (BR-02) |
| **Основной сценарий** | 1) Определение next step 2) Создание задач 3) История перехода |
| **Альтернативы / исключения** | Нет назначений на следующем этапе в RouteInstance — не должно возникать, если RouteInstance валиден; иначе ERR_INTERNAL + лог |
| **Postconditions** | Заявка остаётся `in_approval` |
| **Связи** | BR-02, BR-03; AC-APP-05 |

| **Postconditions** | BR-17; задач открытых нет |
| **Связи** | BR-17; UC-07; AC-APP-05b |
