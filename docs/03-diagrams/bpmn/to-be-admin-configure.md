# BPMN-03 — Настройка типа заявки и маршрута (TO-BE)

**Проект:** Employee Service  
**Тип диаграммы:** Process (BPMN 2.0)  
**Файл индекса:** [bpmn-description.md](./bpmn-description.md)

---

## 1. Назначение

TO-BE процесс конфигурации администратором: тип заявки, поля формы, последовательный маршрут, этапы, назначения; активация / деактивация типа.

Процесс не создаёт заявки от имени сотрудника (BR-27). Изменения конфигурации не меняют route snapshot уже отправленных заявок (BR-09).

---

## 2. Pool и Lane

| Элемент | Имя | Роль / назначение |
| :--- | :--- | :--- |
| **Pool** | Employee Service — админ-конфигурация | Граница процесса настройки |
| **Lane** | Администратор | Роль `admin` |
| **Lane** | Система | Валидация маршрута, сохранение, изоляция snapshot запущенных заявок |

RBAC: операции конфигурации — только `admin` (ACL-04). Создание заявок ролью `admin` без `employee` недоступно (ACL-09, BR-27).

| ID | Lane | Название | Описание |
| :--- | :--- | :--- | :--- |
| ST-01 | Система | Проверить роль admin | Доступ к конфигурации (ACL-04) |
| ST-02 | Система | Сохранить тип / поля / маршрут / этапы / назначения | Персистенция конфигурации |

## 5. Message Flow

Между admin и внешними участниками Message Flow для уведомлений **не требуется**: конфигурация не порождает обязательных in-app уведомлений по BR-23 (события BR-23 относятся к задачам согласования и статусам заявок).

При необходимости информирования admin работает в рамках своего UI; отдельный Message Flow в BPMN-03 не моделируется.

## 6. Связь со snapshot и runtime (аннотации)

| Тема | Поведение (существующие BR) | Где видно в runtime |
| :--- | :--- | :--- |
| Route snapshot | Создаётся при первом submit заявки; конфиг после этого не меняет snapshot запущенной заявки (BR-08, BR-09) | BPMN-01 ST-04; AC-APP-10 |
| Новый submit | Новая заявка при первом submit берёт **актуальный** маршрут на момент submit (AC-APP-10b) | BPMN-01 |
| Schema при edit draft/returned | Актуальная схема типа (BR-26) — следствие изменения UT-02 | BPMN-01 UT-02; AC-DRAFT-01 |
| Schema/value после submit | Зафиксированы на submit; смена полей типа не переписывает in-flight данные до returned-edit/resubmit (BR-26, AC-DRAFT-02) | BPMN-01 ST-05 |
| Деактивация типа | Тип скрыт в каталоге; существующие заявки продолжают согласование (BR-10) | AC-CAT-01, AC-CAT-01b |

Новые правила не добавляются.

---

## 7. Текстовое описание потока

1. **SE-01 / ST-01** — только `admin`.
2. Admin настраивает тип, поля, маршрут (последовательные этапы), явные назначения.
3. Сохранение конфигурации не ретроактивно для route snapshot уже отправленных заявок.
4. Активация возможна только при валидном маршруте (BR-18).
5. Деактивация убирает тип из каталога; живые заявки не прерываются.

## 10. Границы

- Реестр заявок и просмотр истории admin (UC-15, FR-ADMIN-07/08) — не отдельный BPMN-процесс.
- Runtime согласования — BPMN-01 / BPMN-02.
- Новые бизнес-правила не вводятся; scope Этапа 2 не расширяется.
