## A–Z / системные имена

### Employee Service
Веб-система личного кабинета сотрудника и сервиса подачи и согласования заявок. Название продукта pet-project.

### Approval Engine
Встроенный механизм последовательного согласования заявок по экземпляру маршрута заявки. Не является внешним BPM-движком.

### First-approve wins
Правило этапа: если на этап назначено несколько согласующих, достаточно одного решения `approve` для перехода заявки на следующий этап (или в статус `approved`, если этап последний).

### Экземпляр маршрута (RouteInstance)
Набор этапов и назначений **конкретной** заявки, зафиксированный при первом successful submit. При resubmit не пересобирается. Канон: [Snapshot Model](../03-diagrams/erd/snapshot-model.md).

### Версия значений полей (FieldValueVersion)
Схема и значения полей на момент successful submit (номер отправки). Решение согласующего привязано к версии; прошлые версии видны в истории заявки.

### JWT
JSON Web Token — целевой способ аутентификации в полной версии (backlog). В MVP демо используется роль в HTTP-заголовке ([ADR](../03-diagrams/architecture/adr-demo-role-header.md)).

## Роли и участники

### Инициатор
Пользователь, создавший заявку. В типичном сценарии — сотрудник. Инициатор отслеживает статус, может отменить заявку в статусах `draft` и `returned`, а также доработать заявку после возврата.

### Сотрудник (`employee`)
Системная роль пользователя личного кабинета. Может создавать заявки из каталога, работать со своими заявками.

### Согласующий (`approver`)
Системная роль пользователя, участвующего в согласовании. Обрабатывает задачи согласования, на которые назначен лично или через роль.

### Администратор (`admin`)
Системная роль для настройки типов заявок, маршрутов, этапов, назначений, справочников (в MVP — backlog / Future).

### Assignee (назначенный)
Пользователь или носитель роли, указанный в назначении этапа и получающий задачу согласования.

## Каталог и заявки

### Каталог заявок (каталог услуг)
Список активных типов заявок, доступных сотруднику для создания заявки (в MVP — seed).

### Тип заявки
Услуга каталога: название, описание, признак активности, схема полей формы и связанный маршрут согласования.

### Поле типа заявки
Элемент схемы формы типа заявки. Определяет, какие данные сотрудник заполняет при создании заявки.

### Заявка
Экземпляр типа заявки, созданный инициатором. Содержит значения полей, статус, привязку к RouteInstance, версии значений, историю и задачи согласования.

### Черновик
Заявка в статусе `draft`, ещё не отправленная на согласование.

### Статус заявки
Текущее состояние жизненного цикла заявки в MVP:

| Код | Смысл |
| :--- | :--- |
| `draft` | Черновик; не на согласовании |
| `in_approval` | На согласовании |
| `returned` | Возвращена на доработку инициатору |
| `approved` | Согласована по всем этапам маршрута |
| `rejected` | Отклонена на одном из этапов |
| `cancelled` | Отменена инициатором |

### Значение поля заявки
Конкретные данные, введённые инициатором по схеме полей типа заявки (working values в draft/returned; в workflow — FieldValueVersion).

### Комментарий
Текстовое пояснение к заявке или к решению по этапу (например, причина возврата или отклонения).

## Согласование

### Маршрут согласования (маршрут)
Упорядоченная последовательность этапов. В MVP маршрут всегда последовательный. Live-конфиг типа vs RouteInstance заявки — см. Snapshot Model.

### Этап согласования (этап)
Один шаг маршрута с порядковым номером и набором назначений согласующих.

### Назначение на этап
Правило, кто может согласовать этап: роль и/или конкретный пользователь.

### Задача согласования
Рабочий элемент для согласующего по конкретному этапу конкретной заявки.

### Очередь задач
Список открытых задач согласования текущего пользователя-согласующего.

### Согласование (approve)
Положительное решение по задаче этапа.

### Отклонение (reject)
Отрицательное решение по задаче этапа. Завершает заявку со статусом `rejected`.

### Возврат на доработку (return)
Решение согласующего вернуть заявку инициатору (`returned`). После редактирования инициатор повторно отправляет заявку; с какого этапа продолжать — BR-06 / OQ-A|OQ-B в Snapshot Model.

### Отмена заявки
Действие инициатора → `cancelled`. В MVP только для `draft` и `returned`.
